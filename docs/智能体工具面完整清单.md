## 6. 三个待核实项（不要据此下结论）

1. **`canvas_prepare_session` 的注册路径**：它不在 `AgentScopeToolkitFactory` 任何 `register` 里，但 `MoonAgentRuntime:794-807` 用 `RequireExternalExecutionEvent` 接住它的调用并外部执行。说明它走的是 harness 的"外部执行"协议而非普通注册——**具体注册点未找到**。若模型真调用它却拿 `Tool not found`，需要单独查。
2. **`approve_storyboard_production` 的描述自述"仅兼容旧流程，不要用"** ——它算不算该删的候选？需要确认是否还有旧会话依赖。
3. **`review_generated_media`** 只在 `critique-enabled=true` 时注册，默认关（`CLAUDE.md` 有记录：自动视觉评审会追加付费调用）。所以实际常驻可能是 39 而非 40。

## 8. 已执行：分镜工具门控（2026-10-17）

**改动**：`AgentScopeToolkitFactory`

```java
public static final String STORYBOARD_TOOLS = "storyboard-tools";
...
toolkit.createSkillToolGroup(
        STORYBOARD_TOOLS, "Storyboard production tools", false, "storyboard");
storyboardTools.tools().forEach(tool -> toolkit.registration()
        .agentTool(toolPipeline.wrap(tool))
        .group(STORYBOARD_TOOLS).apply());
toolkit.registration()
        .agentTool(toolPipeline.wrap(videoMergeTools.tool()))
        .group(STORYBOARD_TOOLS).apply();
```

同时**删掉** `videoMergeTools` 的常驻 `register(...)`——否则它会同时存在两组，常驻那份仍然可见（门控等于没做）。

**门控安全性依据**：`storyboard` 技能的 `allowed-tools` 本来就声明了这 17 个工具（16 分镜 + `merge_storyboard_videos`），激活技能即可见——与 canvas/image 的做法完全一致。

**回归护栏**：新增 `AgentScopeToolkitFactoryTest.storyboardToolsAreGatedBehindStoryboardSkill`，锁三件事：
1. 组存在且含分镜工具（若改回常驻，组为空 → 断言失败）
2. 组初始 **未激活**（否则等于没门控）
3. 组挂在 `storyboard` 技能上（否则模型没有途径激活它）

> 注意：原有测试脚手架把 `storyboards.tools()` mock 成空列表，所以这次改动**原本是测不到的**。已改为返回真实工具名。

**常驻工具面变化**：40 → **23**（-16 分镜 -1 成片合并）。画布设计场景：55 → 38。

## 9. 已执行：创作记忆工具分类门控（2026-10-17）

调研后发现**不能整组门控**——它们在任何提示词与任何 SKILL 里都没被提到，整组门控等于锁死。按调用语义拆成两类：

| 类别 | 工具 | 处理 |
|---|---|---|
| **读取（常驻）** | `get_creative_context`、`extract_creative_constraints` | 保留常驻 |
| **写入/时间线（门控）** | `update_creative_context` | storyboard / image / video / canvas-design 四组 |
| | `save_timeline_manifest`、`get_timeline_manifest` | storyboard / video 两组 |

**依据**：`TurnContextMiddleware:191-200` 每轮已自动注入 `<project-creative-context>`
（`ProjectCreativeContextServiceImpl.promptContext:106-143` 渲染了目标/创意方向/视觉风格/硬软约束/参考/被拒方向/反馈/本轮模式）
以及约束账本（`:198 constraints.extract()` + `:200 appendConstraintLedger`）。
所以这两个读取工具**必须在技能激活前就能调**；而写入与时间线清单只在具体创作任务里才有意义。

**多组挂载**：一个工具可以同时属于多个技能组（画布工具本就是 design+run 双组），
因此按"哪些技能真的需要它"逐个挂，而不是塞进单一组。

**SKILL 同步**（否则锁死）：四个技能的 `allowed-tools` 已补声明——
storyboard / video 加 3 个，image / canvas-design 加 1 个。

**回归护栏**：新增 `creativeReadToolsStayAlwaysOnWhileWriteToolsAreGated`，同时锁两个方向——
读取类必须常驻且**不得**被塞进技能组；写入类必须按技能出现（如 `save_timeline_manifest`
在 video 组、不在 image 组）。

**常驻工具面**：23 → **20**。画布设计场景：38 → 35。
