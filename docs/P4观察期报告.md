## 0. 一句话结论

**P5 不能做。** 真实流量里 `apply_plan` 只有 **2 次**调用，而逐节点/逐边工具 **189 次**（10-16 当天）。
在模型几乎不用整图提交的情况下删掉逐节点工具，等于把唯一能走通的路砍掉。

同时发现一个**比工具数量更重要的问题**：`create_edge` 在一次 turn 里连续失败 6 次，
错误是 `source/target 不能为空`——模型拿不到节点 id。

## 4. 最有价值的发现：create_edge 失败的根因

### 4.1 `source/target 不能为空`（6 次中的 5 次，同一会话）

`canvas_graph_create_edge` 的参数是**真实节点 id**（`source` / `target`）。而模型手里通常只有：
- 自己刚建的节点的 **ref 名**（`g1`、`m1`）
- 或节点的 **label**（"文生图"）

它没有把 ref 换成 id，于是传了空值 → 连续 5 次全挂，白费轮次。

**而 `apply_plan` 恰好解决了这个问题**——它的 `refs` 机制就是"你写 `g1`，服务端自己换成 id"：

```
"给每个节点一个 ref（如 \"g1\"），再用 refs 声明它的上游来源——
 \"m1\" 表示引用该节点输出，\"g1.result.0\" 表示引用 g1 的第 1 个结果槽输出；
 端口与有序位次由服务端按端口表自动选择"
```

**所以真正的结论是**：模型**需要**的是 `apply_plan`，但它在用 `create_edge` 并失败。这不是"工具太多"的问题，是**好工具没被用起来**的问题。

### 4.2 另外两个独立的失败根因（各 1 次，但都指向真 bug）

| 错误 | 含义 | 为什么要盯 |
|---|---|---|
| `未知画布节点类型: videoGeneration` | `videoGeneration` 是 CLAUDE.md 明确的 **canonical kind**（前端只认它与 `imageGeneration`），却被服务端拒绝 | 要么画布服务版本滞后（`CanvasNodeRegistry` 未含该 kind），要么前端/服务端契约漂移。**与工具收敛无关，是独立缺陷** |
| `首帧 最多连接 1 条` | 端口上限校验生效 | 属正常校验，但错误消息未给出"已连了哪条、该断开哪条"，模型难以自修 |

## 5. 对我前几轮判断的修正

| 我之前说的 | 实测 |
|---|---|
| "旧 `canvas_*` 浏览器工具还在被调用，60 次浪费" | **错**。它们全部集中在 **2026-09-30 一天**，是浏览器桥迁移前的历史残留，**当前不是问题** |
| "删掉 3 个读工具风险很低" | **偏乐观**。10-16 当天它们被调用 **13 次**（get_context 4 + list_nodes 5 + list_edges 4），25 次历史调用全部成功。删掉是真行为变更 |
| "P5 前提条件已成立，可以删" | **错**。前提是"能力覆盖"，但实测模型**不用**那个覆盖能力 |

## 7. 建议的下一步（按收益排序）

### 1. 让 apply_plan 可用起来（收益最大）

- 那次失败是 **6 项校验错误一次性汇总**。模型拿到 6 条错误后没有重试成功——需要确认错误消息是否可操作。
- 建议：`PLAN_INVALID` 的 `details.errors[]` 里每条都带 `example`（最小正确写法），而不是只说"未通过校验"。
- 考虑把 `continueOnError` 默认改为 `true`：一次 turn 里 6 个错误全丢，比部分成功更糟。**这与"整批不落库更安全"的既有设计冲突，需要产品决策。**

### 2. `create_edge` 空参数的防御

错误 `source/target 不能为空` 现在只说"不能为空"。应改成：

```
source/target 不能为空。你用的是 ref 名（g1）还是节点 id？
- 已知节点 id：[列出当前画布的 nodeId]
- 或用 canvas_graph_apply_plan 的 refs，让服务端自动换 id
```

这比删工具更能减少无效轮次。

### 3. 部署后复测 P4 影响

P4 已上线（代码层面），需观察：
- 被删 3 个工具是否出现 `Tool not found`
- 首轮读取是否从 4 次降到 1–2 次（`get_state` 已覆盖）

### 4. 观察期建议时长

当前真实流量集中在 **10-15、10-16 两天**，日均 75–141 次画布调用。按此密度，
**3–5 个完整使用日**足够判断 P4 影响。
