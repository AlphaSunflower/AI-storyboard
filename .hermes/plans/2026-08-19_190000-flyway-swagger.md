## Task 1: 主后端接入 Flyway

**Objective:** 主后端启动时自动迁移 ai_storyboard 库。

**Files:**
- Modify: `AIStoryboardBackend/pom.xml`（dependencies 段，lombok 之后加）
- Modify: `AIStoryboardBackend/src/main/resources/application.yml`

**Step 1: 加依赖**

```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-database-postgresql</artifactId>
</dependency>
```

版本不写——SB 4.0.0 parent 管理（11.14.1，已核实 spring-boot-dependencies-4.0.0.pom）。

**Step 2: 配置（application.yml 共享段）**

```yaml
spring:
  flyway:
    # 老库接管：现有表已包含 V1-V9(修复后 V10) 全部结构。
    # baseline-version 必须大于所有现有脚本版本（用 100）——若设 1，
    # Flyway 会重跑 V2+ 撞"表已存在"；设 100 则全部跳过，只记一行 BASELINE。
    baseline-on-migrate: true
    baseline-version: 100
```

**Step 3: 编译验证**

Run: `"/e/Development/apache-maven-3.9.15/bin/mvn.cmd" -f "E:\Desktop\AI-storyboard\AIStoryboardBackend\pom.xml" compile -q`（先 `export JAVA_HOME="C:\\Program Files\\Java\\jdk-21"`）
Expected: BUILD SUCCESS，无异常

**Step 4: 启动验证**

Run: 启动主后端（本地 8082，profile=local）
Expected: 日志出现 `Successfully applied N migrations` 或 baseline 记录；psql 验证：

```bash
PGPASSWORD=123456 psql -h localhost -U postgres -d ai_storyboard -c "select version, description, success from flyway_schema_history;"
```

Expected: 一条 baseline 行（version=1, success=t）且**不执行** V1-V9（表已存在，避免重复建表冲突）

**Step 5: 幂等验证**

重启主后端一次，确认无报错、history 表无新增行。

**Step 6: Commit**

## 风险与权衡

1. **springdoc 2.8.16 与 SB4 兼容性未官方确认**（springdoc 官方声明支持至 SB 3.5）。预期可用（jakarta 命名空间未变），但若启动报错或 `/v3/api-docs` 404：
   - 备选 A：springdoc 3.x（若已发布，查 maven central `org/springdoc` 最新版）
   - 备选 B：降级仅主后端加 Swagger，网关/MoonAgent 用 actuator 信息替代
   - 验证在 Task 4 Step 3 拦下，不影响 Flyway 部分
2. **baseline-on-migrate 语义**：现有 11/7 张表视为 baseline=1 已存在状态，**V1-V9/V1-V8 历史脚本不会被 Flyway 执行**（它们只用于新环境？不对——新环境 Flyway 会从 V1 开始全执行，旧环境 baseline 跳过。两套行为一致的前提是历史脚本幂等可执行。新库从零跑 V1-V9 需验证脚本可连续执行（含重复 V9 在 Task 2 修复后唯一））。**补充验证**：在空库（如 ai_storyboard_flyway_test）跑一次全量迁移确认 V1-V10 连续成功，再 drop 测试库。
3. **MoonAgent 不配 Flyway**：agent 表（V2-V5）由主后端迁移管理，MoonAgent 部署顺序须先于主后端建表？实际主后端先行即可；若将来 MoonAgent 独立部署环境，再评估同库多 schema 拆分。
4. **Swagger 暴露面**：网关/主后端 swagger 会暴露接口结构（含 /admin/** 路径名）。仅内网/开发环境暴露——生产 profile 用 `springdoc.api-docs.enabled=false` 关闭，本计划生产配置不动，默认只在 local 验证。
