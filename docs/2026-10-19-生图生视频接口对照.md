# 生图 / 生视频接口对照：厂商模式 vs 我们的网关契约

> 日期：2026-10-19
> 目的：把主流生图/生视频接口归纳成几种协议模式，对照我们对外 API 与 `params_schema` 配置能力，回答「哪些能无代码接、哪些必须写适配器」。

---

## 1. 我们的对外接口

### 1.1 生图

| 能力 | 方法 / 路径 | 请求 | 响应 |
|---|---|---|---|
| 文生图 / 通用生图 | `POST /v1/images/generations` | JSON：`model`、`prompt`、`n`、`size`、`quality`、`style` + Spec 参数 | 配置了 `response.sync` 时归一化为 `{created,data:[{b64_json\|url}]}`；否则透传上游 |
| 图生图 / 图片编辑 | `POST /v1/images/edits` | multipart：`model`、`prompt`、`image`、`mask`、`size`、`n` | 透传上游（豆包有专用转换）；暂不做响应归一化 |
| 文本 / 视觉理解 | `POST /v1/chat/completions` | OpenAI chat JSON；`stream=true` 走 SSE | OpenAI 格式 / SSE |
| 模型目录 | `GET /v1/models` | 可选 `type` | 每模型带 `params`、`params.spec`、`is_default` |

### 1.2 生视频

| 能力 | 方法 / 路径 | 请求 / 响应 |
|---|---|---|
| 创建任务 | `POST /v1/videos` | JSON：`model`、`prompt`、`size`、`resolution`、`aspectRatio`、`duration`、`negativePrompt?`、`seed?`、`imageUrl?`、`referenceImages?` → `{vendor,taskId,status}` |
| 轮询 | `GET /v1/videos/{taskId}` | `{taskId,status,progress?,error?}`；`queued/running→processing`，`succeeded/failed` |
| 下载 | `GET /v1/videos/{taskId}/content` | 二进制流（网关注入上游 Key，业务不接触限时 URL） |
| 取消 | `DELETE /v1/videos/{taskId}` | 按厂商能力取消/删除任务 |
| 文件上传 | `POST /v1/files/upload` | 原始 multipart → `{file_id}`（部分厂商需要先传文件） |

### 1.3 设计取向

- **对外只暴露 OpenAI 风格契约**：业务不感知 MiniMax/Veo/Kling 的字段差异。
- **请求差异**用 `model_config`（`upstreamKey` / `map` / `aliases`）+ 路由 `param_overrides` 解决；
- **响应差异**用 `response.sync/async` 归一化；
- **协议差异**（multipart、签名、布尔 operation、队列）下沉适配器。

## 2. 生图接口的四种模式

| 模式 | 代表厂商 | 创建 | 查询 | 媒体返回 | 我们的接入 |
|---|---|---|---|---|---|
| **OpenAI 同步 JSON** | OpenAI、Azure OpenAI、Laozhang、多数中转 | `POST /v1/images/generations` | 无（同步） | `data[].url` 或 `data[].b64_json` | ✅ 直接透传 + `response.sync`，基本零代码 |
| **原生同步 JSON** | Google Gemini / Imagen | `POST /v1beta/models/{model}:predict` | 无 | `predictions[].bytesBase64Encoded` 等 | 适配器转换请求/响应；Spec 描述字段与默认值 |
| **同步二进制 / multipart** | Stability AI | `POST /v2beta/stable-image/generate/*`（multipart） | 无 | 直接返回图片字节 | 必须适配器；当前只有图改图 multipart 代理 |
| **异步任务** | 阿里 DashScope Wanx、火山 Ark Seedream、Replicate、fal | `POST ...` → `task_id` / `prediction id` / `request_id` | `GET /tasks/{id}` / `GET /predictions/{id}` / 队列 status | `results[].url` / `output[]` / `images[].url` | 适配器 + `response.async`；轮询/下载统一 |
| **无官方 API** | Midjourney | 第三方代理 | 第三方 | 第三方 | 不建议作为一级渠道 |

常见字段差异：

| 我们的 canonical | 常见厂商字段 |
|---|---|
| `model` | `model` / `deployment` / `version` / `model_id` |
| `prompt` | `prompt` / `text` / `input.prompt` |
| `size` | `size` / `width`+`height` / `resolution` |
| `aspect_ratio` | `aspect_ratio` / `ratio` / `size` 字符串 |
| `n` | `n` / `num_images` / `num_outputs` |
| `image` / `reference` | `image` / `init_image` / `reference_images` / `subject_reference` |
| `mask` | `mask` / `mask_image` |
| `response_format` | `response_format` / `output_format` |

## 3. 生视频接口的四种模式

| 模式 | 代表厂商 | 创建 | 查询 | 媒体返回 | 我们的接入 |
|---|---|---|---|---|---|
| **OpenAI Videos** | OpenAI Sora | `POST /v1/videos` | `GET /v1/videos/{id}` | `GET /v1/videos/{id}/content` | ✅ 契约最接近；`response.async` + content 下载 |
| **Operation（长任务）** | Google Veo | `POST .../{model}:predictLongRunning` | `GET /v1beta/{operation}`，`done: true/false` | `generatedSamples[].video.uri` | 适配器；`statusPath=done`、`stateMap true/false` 可部分配置 |
| **Task / poll** | MiniMax、Kling、Runway、Luma、Seedance、Wan | `POST ...` → `task_id` | `GET .../{task_id}` | `video_url` / `output[]` / `content.url` | 适配器 + `response.async` |
| **Queue / webhook** | fal、Replicate | `POST queue` / `POST predictions` | `status_url` / `GET predictions/{id}` | `output` URL | 适配器；当前只轮询，不接 webhook |
| **文件先传后生成** | MiniMax 等 | `POST /files/upload` → `file_id` | 同上 | 同上 | 已有 `/v1/files/upload` 代理 |

常见字段差异：

| 我们的 canonical | 常见厂商字段 |
|---|---|
| `model` | `model` / `model_name` / `version` |
| `prompt` | `prompt` / `text_prompt` / `content[].text` |
| `duration` | `duration` / `seconds` / `duration_seconds` |
| `resolution` | `resolution` / `quality` / `size` |
| `aspect_ratio` | `aspect_ratio` / `ratio` / `size` |
| `imageUrl` | `image_url` / `first_frame_image` / `image` |
| `referenceImages` | `reference_images` / `subject_reference` / `image_list` |
| `negativePrompt` | `negative_prompt` / `negativePrompt` |
| `seed` | `seed` / `random_seed` |

## 4. 我们的 Spec 如何对应这些模式

### 4.1 OpenAI 同步生图（零代码）

```yaml
protocol: openai_json
modes: [text-to-image]
request:
  - key: size
    type: enum
    options: [1024x1024, 1536x1024]
    default: 1024x1024
response:
  sync:
    dataPath: data
    mediaField: b64_json
    fallbackField: url
    stripDataUri: true
```

### 4.2 异步任务视频（适配器 + 配置）

```yaml
protocol: openai_json
modes: [text-to-video, image-to-video]
request:
  - key: duration
    type: enum
    options: [4, 6, 8]
    default: 6
response:
  async:
    taskIdPath: task_id
    statusPath: status
    stateMap:
      queued: queued
      processing: running
      success: succeeded
      fail: failed
    mediaPath: video_url
    mediaMode: media_url
    pollIntervalSec: 5
    timeoutSec: 300
```

### 4.3 Veo 式 operation

```yaml
response:
  async:
    taskIdPath: name            # operation name
    statusPath: done            # boolean
    stateMap:
      "true": succeeded
      "false": running
    mediaPath: response.generateVideoResponse.generatedSamples[0].video.uri
```

注意：数组下标、operation 路径、错误结构仍建议适配器处理；Spec 只能覆盖「点路径 + 状态映射」的简单情况。

### 4.4 fal / Replicate 队列

```yaml
response:
  async:
    taskIdPath: request_id
    statusPath: status
    stateMap:
      IN_QUEUE: queued
      IN_PROGRESS: running
      COMPLETED: succeeded
      FAILED: failed
    mediaPath: images[0].url
```

同样，`status_url/response_url` 这种「先查状态再换 URL」的协议需要适配器；Spec 负责输出契约。

### 4.5 键名与值映射

```yaml
request:
  - key: pictures          # 业务通用键
    upstreamKey: pics      # 上游键
    aliases: [photos]      # 兼容旧请求
    map:
      2K: 2048x2048
```

- 模型级 `upstreamKey` 解决「所有渠道都叫 pics」；
- 路由 `param_overrides.rename` 解决「A 渠道 pics、B 渠道 pictures」；
- `map` 解决「UI 2K、上游 2048x2048」。

## 5. 对照结论

### 我们能稳定覆盖的

- OpenAI / Azure / 中转的同步生图：**配置即可**；
- MiniMax / Kling / Runway / Luma / Seedance / Wan 的「创建→轮询→下载」：**适配器 + Spec**，新增厂商主要是适配器；
- 参考图/首帧/尾帧、尺寸/比例/时长、负向提示词、种子：Spec 参数 + 映射可表达；
- 响应归一化：图片 `data[]`、视频 `taskId/status/media` 已覆盖大部分；
- 多渠道负载、上游模型名映射、参数覆盖、跨模型回退：已具备。

### 还需要补的

| 优先级 | 缺口 | 影响 |
|---|---|---|
| P0 | 二进制/图片字节响应模式（Stability） | 现在只能透传，无法统一成 `data[]` |
| P0 | Operation / 布尔状态 / 嵌套数组路径 | Veo 这类需要适配器或更强的路径语法 |
| P1 | Webhook/回调 | fal/Replicate 可不用轮询，当前只支持轮询 |
| P1 | 带签名的上传/下载（S3、OSS、Kling JWT） | 需要适配器，配置层无法表达 |
| P1 | 多段视频 / 时间线合并 | 目前是单任务，长视频由 Agent 侧编排 |
| P2 | 取消语义差异 | 有的删除、有的 cancel、有的不支持 |
| P2 | 价格/配额/速率 | 网关尚未做计费与配额 |

### 一句话

**我们对外是一套 OpenAI 风格契约；厂商接口可以归成「同步 JSON / 同步二进制 / 异步任务 / Operation / 队列」五类。**
前两类里的 JSON 部分可以无代码；后三类和 multipart/签名类，正确做法是「适配器负责协议，Spec 负责字段、默认值、映射、响应归一化」。
