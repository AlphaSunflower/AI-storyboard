# 模型配置工作台（生图 / 生视频无代码配置）

> 落地日期：2026-10-18
> 入口：网关管理后台 `#/models`（「模型配置」）
> 目标：把生图/生视频模型的参数、能力、默认值和响应映射，从手写 JSON/YAML 变成可视化配置 + 样例试运行。

---

## 1. 它解决什么

原来配置一个生图/生视频模型需要：

1. 在路由弹窗里填一堆固定滑块；
2. 再手写一段 `params_schema` JSON；
3. 视频还要猜 `taskIdPath/statusPath/mediaPath/stateMap`；
4. 保存后只能靠真实调用验证，错了表现为「图片不出来 / 视频一直 processing」。

现在：

- 参数是表格，一行一个参数；
- 能力（文生图/图生图/文生视频/图生视频）是勾选；
- 枚举值到上游值的映射（`2K → 2048x2048`）是映射表；
- 响应映射是表单，粘贴真实响应即可试运行；
- 所有配置仍落到同一个 `model_params.params_schema`，YAML/JSON 代码视图和导入导出保持兼容。

## 2. Spec 扩展

在原有 mini-spec 上新增：

| 字段 | 作用 |
|---|---|
| `protocol` | 协议模板：`openai_json` / `openai_compatible` / `multipart` / `gemini` / `minimax` / `ollama`；实际适配器仍由渠道类型决定 |
| `modes` | 能力模式：`text-to-image`、`image-to-image`、`text-to-video`、`image-to-video`、`reference-to-video` |
| `visibleWhen` | 某模式下才展示：`{"mode":"image-to-image"}` |
| `requiredWhen` | 某模式下必填：`{"mode":"image-to-image"}` |
| `map` | UI 值 → 上游值映射：`{"2K":"2048x2048"}` |
| `injectDefault` | 缺失时由网关补 `default`；不勾=只作为 UI 默认值 |
| `upstreamKey` | 上游实际键名；空=同 `key`。用于 `pictures` → `pics` 这类键名差异 |
| `aliases` | 兼容旧键/别名的数组；请求里出现别名时自动归一成 `upstreamKey` |
| `maxItems` | 上传/数组参数上限（如参考图最多 4 张） |

示例（生图）：

```yaml
protocol: openai_json
modes: [text-to-image, image-to-image]
request:
  - key: pictures             # 通用键：Agent/画布使用
    upstreamKey: pics         # 上游实际键名
    aliases: [photos, refs]   # 兼容旧请求键
    label: 参考图
    type: array
    role: image_upload
    cardinality: multi
    maxItems: 4
  - key: size
    label: 尺寸
    type: enum
    options: [1K, 2K, 4K]
    default: 2K
    map: { 1K: 1024x1024, 2K: 2048x2048, 4K: 4096x4096 }
response:
  sync:
    dataPath: data
    mediaField: b64_json
    fallbackField: url
    stripDataUri: true
```

示例（生视频）：

```yaml
protocol: openai_json
modes: [text-to-video, image-to-video]
request:
  - key: duration
    type: enum
    options: [4, 6, 8]
    default: 6
  - key: resolution
    type: enum
    options: [768P, 2K]
    default: 768P
  - key: image
    role: image_upload
    cardinality: single
    requiredWhen: { mode: image-to-video }
response:
  async:
    taskIdPath: task_id
    statusPath: status
    stateMap: { queued: queued, processing: running, success: succeeded, fail: failed }
    mediaPath: content.url
    mediaMode: media_url
    pollIntervalSec: 5
    timeoutSec: 300
```

`ParamsSchemaValidator` 会校验上述字段；非法结构在保存前被拒绝。

## 3. 界面

「模型配置」页 = 顶部横向模型列表 + 下方编辑器：

- **模型列表**：顶部横向排列，支持按模型名、生成类型、绑定渠道筛选；
- **从模板创建**：豆包 Seedream 4.0 / 5.0 Flash、MiniMax H3、OpenAI 兼容生图；选模板 + 渠道（可新建）+ 模型名，一次生成模型配置和路由；
- **能力与协议**：协议模板下拉、模式勾选；
- **请求参数**：键/上游键/别名/显示名/类型/最小/最大/选项/默认/注入/值映射/模式条件/展示/上传角色/单多/上限；「注入」勾选表示缺失时网关会补这个默认值；
- **从请求体识别**：粘贴一条业务/Agent 真实请求 JSON，按请求里的字段名自动生成参数行，不用自己发明标准名；
- **标准键建议**：「键」输入框带标准参数下拉（size/duration/image/temperature…），选中后自动补显示名/类型/角色；自定义键仍可直接输入；
- **请求预览**：路由弹窗内输入一段业务请求，查看原始 → 模型默认值/映射后的最终 JSON，以及目标 URL 和步骤；不调用上游；
- **响应映射**：同步（图片）与异步（视频）分开；视频含任务/状态/媒体/下载/轮询/超时；
- **表单预览**：按模式渲染 Agent/画布将看到的控件（只读）；
- **样例试运行**：粘贴上游响应 → 归一化结果；
- **高级 JSON 视图**：嵌套 `object/arrayofobject` 等表格覆盖不到的场景，直接编辑整份 Spec。

保存时先调 `/admin/model-params/validate`，再 `PUT /admin/model-params` 写入 `params_schema`；
模型目录缓存会自动失效。

### 3.0 默认值是否注入

`schema.default` 默认只是 UI 默认值：Agent/画布用它预填，调用方不传时网关不会自动补。
需要网关补齐时，在参数行勾「注入」（Spec 里 `"injectDefault": true`）：

```json
{"key":"size","type":"enum","options":["1K","2K"],"default":"2K","injectDefault":true}
```

- 只在调用方没传该键、也没传别名时补；
- 不覆盖调用方显式值；
- `n` 这类厂商不认的字段不要勾，避免把参数硬塞给上游；
- 模板里的 `size/watermark/response_format/duration/resolution/aspect_ratio` 已默认勾选。

### 3.0.1 键名从哪来

「键」不是配置人员发明的，它等于**业务/Agent 真正发给网关的 JSON 字段名**：

- 不知道字段名：点「从请求体识别」，粘贴一条真实请求，系统按请求里的键自动建行（跳过 `model/prompt/stream`）；
- 字段名已知：从「键」下拉选标准键，自动补显示名/类型/角色；
- 上游叫法不同：只填「上游键」（例如 `image` → `pics`）；同名时上游键留空；
- 旧客户端叫法不同：填「别名」，网关会归一成上游键并移除旧键。

### 3.1 一键模板

页面右上角「从模板创建」内置：

| 模板 | 内容 |
|---|---|
| 豆包 Seedream 4.0 | 1K/2K/4K、参考图、n、watermark、response_format、同步响应映射 |
| 豆包 Seedream 5.0 Flash | 1K/1.5K/2K、单图、参考图上限 10、同步响应映射 |
| MiniMax H3 | duration/resolution/aspect_ratio/首帧图、异步任务映射 |
| OpenAI 兼容生图 | 1024x1024 等尺寸、n、同步响应映射 |

模板会：

1. 复用同名/同 BaseURL 的渠道，或新建渠道（填 Key）；
2. `PUT /admin/model-params` 写入 Schema（同模型已有配置会覆盖，需确认）；
3. 创建或更新「模型 → 渠道」路由。

适合新环境开通模型，或不想手填参数/响应映射时使用。

### 3.2 模型路由只做绑定

路由弹窗只保留「渠道 / 模型类型 / 模型 / 上游模型名 / 优先级 / 权重 / 重试 / 回退 / 默认模型」，
参数配置、参数覆盖、参数 Schema 不再在这里维护：

- 模型没有 `params_schema` 时，弹窗顶部会出现黄色警告和「去模型配置」按钮；
- 存量路由的 `param_overrides` / `default_params` 已由 **V21** 清空，保存时也不会再写入；
- 需要新的默认值/键值映射/响应映射，统一去「模型配置」改。

> V21 `V21__clear_route_param_overrides.sql` 为手动迁移；本地 `llm_gateway` 已执行，其他环境需 psql 执行。

### 3.3 启动 / 冻结

渠道与路由统一使用「启动 / 冻结」状态：

- 路由冻结只下线这一条渠道绑定；
- **渠道冻结时，该渠道下所有模型路由显示「冻结（渠道）」、模型列表显示「冻结」**，运行时 `RouteResolver` 不会再选中该渠道；
- 路由列表提供「启动 / 冻结」按钮；渠道冻结时按钮禁用，需要先到渠道管理启动渠道；
- 渠道管理冻结后，模型目录缓存失效，`/v1/models` 不再返回只有冻结渠道的模型。

## 4. 试运行接口

`POST /admin/model-params/normalize-preview`

```json
{
  "paramsSchema": "{...}",
  "sample": "{\"data\":[{\"b64_json\":\"AAA\"}]}",
  "kind": "sync",
  "taskId": null
}
```

返回：

```json
{
  "valid": true,
  "errors": [],
  "warnings": [],
  "normalized": {"created": 1792338291, "data": [{"b64_json": "AAA"}]}
}
```

- 不调用上游、不落库；
- `kind=async` 时走视频轮询归一化（`stateMap`/`mediaPath`/`mediaMode`）；
- Schema 非法时返回 `valid=false` + 结构化错误，不执行归一化。

> 注意：Spring Boot 4 使用 Jackson 3，接口里返回 `normalized` 时已转成 `Map/List`，
> 不能直接返回 Jackson 2 的 `JsonNode`（会被序列化成 `nodeType/containerNode` 等 bean 属性）。

### 4.1 请求预览

`POST /admin/routes/preview`

```json
{
  "modelName": "doubao-seedream-4-0-250828",
  "type": "image",
  "channelId": "渠道ID",
  "path": "/images/generations",
  "body": "{\"model\":\"doubao-seedream-4-0-250828\",\"prompt\":\"一只橘猫\"}"
}
```

返回：

```json
{
  "channelName": "豆包生成",
  "targetUrl": "https://ark.cn-beijing.volces.com/api/v3/images/generations",
  "upstreamModel": "doubao-seedream-4-0-250828",
  "specFound": true,
  "original": "...",
  "afterSpec": "...",
  "forwarded": "{\"model\":\"...\",\"prompt\":\"...\",\"size\":\"2K\",\"watermark\":false}",
  "steps": ["注入默认值 size=\"2K\"", "setIfAbsent response_format=\"url\""]
}
```

- 不调用上游、不扣费；
- 顺序与线上一致：Spec 默认值/键映射/值映射 → 路由 rename/delete/setIfAbsent/set → upstream_model；
- 非 `openai_compatible` 渠道会返回 `note`，说明请求由适配器构建，`forwarded` 只是适配器输入。

## 5. 键名映射的执行顺序与范围

一次请求的改写顺序：

```
aliases / key → upstreamKey（仅 openai_compatible 透传协议）
        ↓
request[].map 值映射
        ↓
model_route.param_overrides（存量兼容；V21 后管理端不再写入）
        ↓
写入 upstream_model
        ↓
响应归一化
```

- `pictures`（通用键）+ `upstreamKey: pics` + `aliases: [photos]`：
  - 请求带 `pictures` → 上游收到 `pics`；
  - 请求带 `photos` → 上游收到 `pics`，并移除 `photos`；
  - 两者都有 → `pictures` 优先，`photos` 被移除。
- **同一模型不同渠道键名不同**：模型级 `upstreamKey` 只能写一个。当前管理端已不提供路由级 `param_overrides`；如确有渠道差异，暂时拆分模型配置，或等后续做渠道级字段映射。
- **键重命名只对 `openai_compatible` 生效**：Gemini / Ollama / 视频适配器会先解析 canonical 字段再构建厂商载荷，提前改名会让适配器读不到；这些协议仍可用 `map` 做值映射，但键名由适配器决定。
- 图改图 multipart 不做键名/值映射。

## 6. 当前边界

- 表格覆盖扁平参数；嵌套对象/数组用「高级 JSON 视图」。
- `map` 只做值替换，不做单位换算/拼接；复杂变换仍需适配器代码。
- 模式条件目前是「单模式」；多条件（分辨率+时长联动）后续扩展。
- 试运行只验证响应映射，不发真实请求；真实生成测试仍在路由「测试」里。
- 图改图 multipart 仍不复用上游模型/参数改写。
