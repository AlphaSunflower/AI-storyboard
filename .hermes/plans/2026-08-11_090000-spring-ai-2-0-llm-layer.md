# Spring AI 2.0 LLM 调用层优化实施计划

> **For Hermes:** 用 subagent-driven-development 技能逐任务执行（每任务独立子代理 + 规格审查 + 代码质量审查）。
>
> **范围（用户已确认）：** 只优化 LLM 调用层 —— 6 个手写 JDK HttpClient 服务换成 Spring AI 2.0 ChatClient。**Dify 编排（AgentChatService / AgentConversationController）不动；生图/生视频（ImageGenerationService / MinimaxVideoService / VideoGenerationService）不动。**

**Goal:** 引入 Spring AI 2.0.0，把 6 个手写 `HttpClient` 调 LLM 网关的服务改为 `ChatClient`（结构化输出 + 多模态），消除重复的 HTTP 样板代码，行为语义（超时/异常/兜底）不变。

**Architecture:** Spring AI 只当 LLM 调用库（ChatClient + entity 结构化输出 + Media 多模态），**不引入** ChatMemory/RAG/MCP/工具循环（本范围 YAGNI）。每个服务从注入的 `ChatClient.Builder` 构建自己的 ChatClient（`defaultOptions` 固定本服务模型），公共方法签名与异常语义不变 → 调用方零改动。图片/视频生成继续直连（MiniMax/Laozhang 不走 Spring AI）。

**Tech Stack:** Spring AI 2.0.0（`spring-ai-bom` + `spring-ai-starter-model-openai`）+ Spring Boot 4.0.0 + JDK 21；LLM 网关（OpenAI 兼容 `/v1/chat/completions`，本机 8083）作为唯一 upstream。

## 背景与现状（已核实，2026-08-11）

6 个待转换服务，全部 `HttpClient` 直连 `AiConfigProperties.getGatewayBaseUrl() + "/v1/chat/completions"`，模型/超时/输出形态各异：

| # | 服务 | 文件 | 模型 | 超时 | 输出 | 多模态 | 调用方 |
|---|------|------|------|------|------|--------|--------|
| 1 | ScriptGenerationService | `service/ai/ScriptGenerationService.java` | `defaultVisionModel`（gemini-3-flash-preview） | 120s | JSON 数组 → 分镜列表 | 否 | `AIController:57` |
| 2 | PromptOptimizeService | `service/agent/PromptOptimizeService.java` | `defaultVisionModel` | 60s | 纯文本 | 否 | `AgentConversationController` |
| 3 | ConversationTitleService | `service/agent/ConversationTitleService.java` | gemini-3.5-flash-lite + `thinking_level=minimal` | 30s | 纯文本 | 否 | `AgentChatService:315`（异步） |
| 4 | IntentRecognitionService | `service/agent/IntentRecognitionService.java` | deepseek-v4-flash | 30s | 纯标识符（白名单） | 否 | `AgentChatService`（Dify 主流程内同步） |
| 5 | ImageRefinePromptService | `service/ai/ImageRefinePromptService.java` | `defaultVisionModel` | 120s | JSON `{image_analysis, modifications, refined_prompt}` | **是**（本地图 base64 data URI） | `AgentChatService:868` |
| 6 | VideoPlanService | `service/ai/VideoPlanService.java` | `defaultVisionModel` | 120s | JSON `{message, duration}` → `VideoPlan` record | **是**（同上） | `AgentChatService:942` |

关键现状事实：
- `pom.xml` 无任何 Spring AI 依赖（SB 4.0.0 parent）。
- 网关配置在 `application.yml` `ai.gateway.base-url: ${LLM_GATEWAY_BASE_URL:http://localhost:8083}`、`ai.gateway.api-key: ${LLM_GATEWAY_API_KEY:}`；原始 HTTP 调用拼 `{baseUrl}/v1/chat/completions`。
- 每个服务自带：connectTimeout 30s 的 HttpClient、`objectMapper`、错误包装 `RuntimeException("xxx: " + e.getMessage())`、JSON 提取兜底（markdown 代码块剥离 + `{...}` 截取）。
- Spring AI 2.0.0 + SB 4.0.0 编译/启动/`ChatClient.Builder` 装配已被隔离 spike 验证 PASS（见技能 `spring-ai-2-0-development`；依赖树泄漏断言必须限定 groupId `org\.springframework\.ai:spring-ai[^:]*:jar:(1\.|0\.)`）。

## 关键设计决策（含待 spike 验证的决策点）

1. **版本与坐标**：`spring-ai-bom:2.0.0`（dependencyManagement import）+ `spring-ai-starter-model-openai`。绝不引入 1.x 坐标。
2. **网关接入**：`spring.ai.openai.base-url = ${LLM_GATEWAY_BASE_URL:http://localhost:8083}/v1`（Spring AI OpenAI 客户端在 base-url 后自动拼 `/chat/completions`，与现网路径等价）；`spring.ai.openai.api-key = ${LLM_GATEWAY_API_KEY:}`。`AiConfigProperties` 不改（仍服务其余 HttpClient 调用方）。
3. **每服务一个 ChatClient**：注入 `ChatClient.Builder`，`builder.defaultOptions(OpenAiChatOptions.builder().model(XX).build()).build()` 固定模型（2.0 Options 不可变，用 builder/mutate；确切 API 以 spike 为准）。
4. **结构化输出**：ScriptGenerationService / ImageRefinePromptService / VideoPlanService 用 `chatClient.prompt().call().entity(...)`；**保留现有防御式解析（`extractRefinedPrompt` / `extractVideoPlan` / `parseScenes` 的 markdown 剥离 + 截取兜底）作为 entity() 失败时的 fallback**（迁移设计明确"保留容错解析层"，gemini 系 JSON 输出实测需要）。
5. **多模态**：本地图继续读文件转 base64 data URI（`data:image/png;base64,...`），以 `Media`（`Media.builder().data(dataUri).mimeType(...)` 或等价 2.0 API）放入 `UserMessage`。data URI 支持性 **spike 验证**；不支持则改用 `Media.builder().data(bytes, mimeType)` 原始字节。
6. **thinking_level（决策点 D1）**：spike 验证 `OpenAiChatOptions`（或其内部扩展点）能否携带自定义顶层参数 `thinking_level`。结论分叉：
   - 支持 → ConversationTitleService 照传 `minimal`（语义自文档化，行为与现状一致）；
   - 不支持 → **丢弃该参数**（实测注释已证明 gemini-3.5-flash-lite 默认 minimal 思考，参数是冗余的"语义自文档化"），注释保留说明。**不做**自写请求拦截器/自定义 RestClient 传参（复杂度不值）。
7. **超时（决策点 D2）**：spike 验证 Spring AI 2.0 OpenAI 超时配置（`spring.ai.openai.timeout.*` 或 `OpenAiApi` 构造参数）。结论分叉：
   - 有全局超时配置 → 统一设 120s。注意回归：IntentRecognitionService（现 30s，Dify 主流程**同步**调用）与 ConversationTitleService（现 30s，异步）最坏阻塞变 120s。意图识别失败兜底 `intent-other` 语义不变，只是最坏情况慢；标题服务异步无感知。→ 默认接受，注释说明；
   - 无超时配置或用户不接受 → 这两个服务**保留 HttpClient 直连**（`pom.xml` 加不加 Spring AI 都不影响），文档注明原因。
8. **行为红线**（转换时逐条核对）：公共方法签名不变；错误包装信息格式不变（前端 `GlobalExceptionHandler` 依赖 `e.getMessage()` 透传）；意图白名单 + `intent-other` 兜底不变；`cleanTitle`/`cleanType` 清洗逻辑不变；文本截断（500/200 字）不变；`VideoPlan.isValid()` 4~15 校验不变。
9. **不引入**：ChatMemory（无会话状态需求）、RAG/VectorStore（无外部知识）、MCP（无外部工具）、@Tool 工具循环、Advisor（无横切需求）——全部 YAGNI，本范围不需要。

## Phase 2 — 逐服务转换（每服务一任务，公共签名/异常/兜底不变）

> 通用转换模式（除多模态外 6 个服务一致）：
> 1. 删 `HttpClient`/`objectMapper` 字段与构造参数里的样板；注入 `ChatClient.Builder`；
> 2. `private final ChatClient chatClient;` 构造器里 `chatClient = builder.defaultOptions(OpenAiChatOptions.builder().model(MODEL).build()).build();`
> 3. 请求：`String content = chatClient.prompt().system(SYS).user(USER).call().content();`
> 4. 现有解析/清洗/兜底方法（`parseScenes` / `extractRefinedPrompt` / `cleanTitle` / `cleanType` 等）**原样保留**；entity() 失败时走原解析兜底；
> 5. 错误包装保留：`throw new RuntimeException("XX失败: " + e.getMessage(), e)`；catch `Exception`（含 Spring AI 的 `RuntimeException` 系）。
> 6. 每次转换后 `mvn compile -q` 必须通过；调用方（Task 0 表格列出的行）零改动。
