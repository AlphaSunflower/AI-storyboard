## 3. 评委语言对照表（技术黑话 → 评委语言）

这是本次优化的灵魂。每个功能先给**评委看得懂的"人话"**，再给一句话创新点/优势。表内左侧为原文（或应删改的），右侧为替换文案。

| 技术黑话（原文/现稿） | 评委语言（替换文案） |
|---|---|
| 分镜生成：意图识别→澄清→方案→HITL→写库（JSON 结构化存储） | **一句话分镜**：说一句"帮我做 30 秒咖啡广告"，AI 自动给出专业分镜脚本（镜头/画面/运镜/台词/时长），不用懂电影分镜。 |
| SSE 流式打字机 | AI 回答**像打字一样逐字实时显示**，不用等整段加载，体验跟聊天软件一样。 |
| HITL checkpoint：form_token 一次性消费 + 30 分钟过期 + plan JSON 落库 | **确认点不丢稿**：AI 每个关键决定都让你先确认；哪怕中途断网、刷新、关机，你已确认的进度都会**自动恢复**，绝不白干。 |
| 虚拟线程 + CompletableFuture 异步轮询 | **长任务不卡界面**：生成视频要点时间，AI 在后台悄悄跑，你照常操作别的，好了自动提醒。 |
| 策略模式 + 注册表 + @Component | **即插即用**：每加一个新创作能力，不用改核心架构，像插 U 盘一样装上就能用（所以平台能一直加新模型/新玩法）。 |
| LLM 网关统一抽象（文本/图像/视频/理解四类 REST） | **一套接口接多家 AI**：画图、写文案、做视频、看图的模型都统一接入；哪家好用/便宜就切哪家，上游涨价一键切换，用户无感。 |
| asset 资产库 + scene_assets 关联 + 视频首帧一致 | **人物形象锁**：把角色/道具/场景存成"素材库"，跨镜头复用，保证**同一个人物从头到尾脸、衣服、长相不变**（AI 视频最怕"主角变脸"）。 |
| 模型参数智能推荐（resolution/duration/aspectRatio 取值优先级） | **参数免懂**：AI 帮你选好清晰度/时长，并告诉你为什么；想改也能改。 |
| 微服务四服务 + Nacos + 内部 API | **模块独立**：各功能独立运行、坏了一个不连累其他、可单独升级扩容。 |
| JWT 双 token / scrypt 加盐 / AES 加密密钥 | **账号安全**：登录加密、密码不可逆存储、第三方 AI 账单密钥加密保管。 |
| IDOR 归属校验 + 40401 统一文案 | **只看得到自己的**：只能访问自己的项目/素材，防止越权看别人内容。 |
| 私有化部署（容器化 / 数据不出域） | **数据不出门**：整套系统装进企业自己的内网，素材不外传，满足政企合规审计。 |
| 表 4-2 后端框架 Spring Boot 4 / MyBatis-Plus… | **删/降附录**：这是工程师常识，评委不需要，只留一句"采用主流的 Java + React 技术栈，成熟稳定"。 |
| 数据库核心表结构（users/agent_checkpoints…） | **只留结论 + 降附录**：正文一句"数据按归属分为业务库与模型网关库，表结构详见附录 A"；字段细节整个移走。 |

## 6. 风险与开放问题

- **章 XML 块搬移易错**：必须"先定位同级/上级标题，拷贝段落区间"，禁止 deepcopy 散段；搬移后跑标题序列断言 + 图片数断言。若某章块搬移后图片错位，用 `d.inline_shapes` 计数对账。
- **目录是 Word 域**：python-docx 无法刷新，交付后用户须 Ctrl+A → F9。
- **50 张图**：量很大，重排章节块会整块搬运图片，理论零丢失；但若某图是"浮动"而非"内联"，可能不随段移动——探测脚本需先甄别 inline vs floating（`float 时` 需单独处理）。**风险最高点**，若遇到浮动图，退化为"仅重编号标题 + 重编号 caption，不搬图"的保守方案，并提前向用户说明。
- **评委语言是主观判断**：第 3 节对照表为建议稿，用户可对个别措辞再微调；本计划默认按此执行。
- **PESTEL/STP 深度有限**：属教科书套话，评委可能觉得浅；计划里已降为背景一句，如评委要深度可后续补，本版以"能看懂 + 有创新点 + 有优势"优先。
